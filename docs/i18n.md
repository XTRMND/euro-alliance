# Internationalisation

Bulgarian first. English later, using the same templates. Every visible string on badges, bubbles, stickers, pills and buttons is live text, never baked into an image.

## 1. Approach

- **Content** (titles, body, course data, navigation labels, legal texts) is localized in Payload (`docs/cms-schema.md`).
- **Fixed UI strings** (this file) live in `src/messages/bg.json` and `src/messages/en.json`, loaded with `next-intl` (proposed; any library with ICU plurals and server components works).
- **Routes:** Bulgarian at the root (`/kursove`), English under `/en/` with English slugs when it launches. `hreflang` alternates only for pages that actually have English content.
- `<html lang="bg">` on Bulgarian pages, `lang="en"` on English pages.
- **Keys** are `area.element` in camelCase. Add a key here in the same PR that adds it to `bg.json`. A unit test fails if `bg.json` and `en.json` have different key sets, or if a component uses a key that isn't in `bg.json`.
- **Formatting** goes through `src/lib/format.ts` using `Intl` with `bg-BG` / `en-GB`: dates, numbers (non-breaking space as the thousands separator, as in «175 958»), currency. Check the output against the Figma text.
- **Text-transform:** where Figma shows a label in capitals (НИВО, ЕЗИКА), store it in normal case only if the design uses CSS uppercase consistently; otherwise store it as shown. Pick one rule in PR 4 and keep it.

## 2. Source of each value

| Mark | Meaning |
|---|---|
| **B** | From the approved brief. Use as is. |
| **F** | Take the exact Bulgarian text from the Figma node listed. The value here is what we expect to find; **Figma wins** if it differs. |
| **P** | Not in the design. Proposed wording; the user approves it in the PR. |

English values are drafts. The client approves English before it launches (open item).

## 4. How to fill the **F** rows

In each page or component PR: call `get_design_context` on the node, copy each fixed string exactly (including Bulgarian quotation marks „…“ and non-breaking spaces), add the key to `bg.json`, and update the table here. Leave the English value as a draft. Content strings (anything the client will want to edit) go to Payload instead.
