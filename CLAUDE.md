We are replacing euro-alliance.net. The design is complete and approved in Figma (31.10.2026). You build it as a Next.js app with Payload CMS so the client can edit content themselves. ## 2. Stack

- **Next.js** (App Router) + **TypeScript** (strict) + React. Next.js 16 changed APIs and conventions: before using an API you don't know well in this version, read its page in `node_modules/next/dist/docs/`.
- **Runtime:** Node 24 LTS (`.nvmrc`) and pnpm 11 (`packageManager` in `package.json`).
- **Payload CMS** (MIT) installed inside the same Next.js app (`src/app/(payload)`), on **PostgreSQL** (`@payloadcms/db-postgres`), with migrations committed.
- Server-side rendering with CDN caching. Content changes revalidate pages on demand from Payload hooks (`revalidateTag` / `revalidatePath`).
- **Hosting is on the user's own servers. Do not assume Vercel** or any managed platform. Build a portable Node app: `output: 'standalone'`, a Dockerfile, Postgres via `DATABASE_URL`, media storage behind a Payload storage adapter. Ask the user before choosing anything infrastructure-specific (CDN, object storage, SMTP, preview environments, cron).
- **Fonts**, all self-hosted (no runtime request to Google): Sofia Sans and Sofia Sans Extra Condensed as one subset variable WOFF2 each, made by `scripts/build-fonts.sh` (Cyrillic and Latin together, only the weights in use; PR 4); Caveat the same way, in `public/fonts`, declared in `globals.css` and preloaded only on the pages that write by hand (`src/styles/font-hand.tsx`, PR 12).
- **Styling:** CSS Modules with design tokens as CSS custom properties (decided in PR 1). Tokens come from Figma variables and no component hard-codes a colour.
- **Tests:** Vitest (unit), Playwright (smoke and visual), `@axe-core/playwright` (accessibility), Lighthouse CI (budgets).
- Use the current stable versions at scaffold time, pin them, and list them in the PR 1 description.

## 3. Rule one: never invent content

Use only official information from the client or from euro-alliance.net. **Never invent prices, dates, people, numbers, quotes, testimonials, photos or claims.** That includes seed data, fixtures and "realistic placeholders".

- In code, a component hides an element when its CMS field is empty. No «Lorem ipsum», no "TBD", no placeholder image in production.
- When a value is unknown, list it under **Open items** in the PR description so the user can ask the client.
- Unit tests and component fixtures may use obviously fake values (`Test course A`) that can never reach production data.
- Copy shown in the approved Figma file is approved content and may be used as seed data.
- Real photos only, never stock. If a photo is missing, the section that needs it stays hidden until the client supplies one.

## 6. Approved design rules

- **Paper and header:** one warm paper background (bg/warm #F7F3EC) on every section, no colour stripes. Only the navy inquiry band and the footer break it. The white header has a torn bottom edge and a soft shadow.
- **Stickers:** die-cut, duotone, white edge, navy shadow. One sticker, one meaning; never reuse a sticker for a different meaning on the same page.
- **Flags:** real colours with light grain.
- **Program heroes:** language pages use the notebook hero with a flag sticker. All other program pages use the course-page hero (halftone panel, sticker, tape, navy count bubble), never the notebook.
- **Count / level bubble:** navy circle, sand number, small label, tilted −8°.
- **Halftone:** navy dots, 42% on course card panels, 7% on textbook cards. **Never halftone dots over a regular photo.**
- **Photos:** real only. Medium tint (colour + 45% duotone), polaroid or taped. A photo must be understandable without a caption. Tints: hero 88%; news cards 30% on news pages and 55% on the homepage (Tint=Strong); about page photos 45%. They clear to full colour on hover where the design says so.
- **About hero:** torn-paper window showing the team photo (forum 2026), with the small «А» bubble.
- **Lists and pills:** pills always have a visible label above them. Lists use Index card or List row. Paired cards have equal heights. 32 px between cards.
- **Highlighter:** a sand highlighter on one phrase per headline, never more.
- **EU logo strips:** exactly as supplied (publicity rules). No recolouring, cropping, tinting or reordering.

## 7. Behaviour (summary; the full spec is `docs/motion.md`)

- One-time landing motion per page: copy fades up about 30 px, hero art settles. Ease-out, about 0.85 s. Nothing loops except the strips and the globe.
- Language strip and partner logos: 56 px tall, about 18 px/s, pause on hover.
- Homepage globe: turns only while the page scrolls (about 0.22° per px), eased, stops when scrolling stops.
- Hovers: buttons 0.15 s, cards 0.25 s, news 0.35 s.
- `prefers-reduced-motion`: no landing motion, no moving strips, the globe stays still.
- Cookie consent with equal-weight «Само задължителни» and «Приеми всички», «Настройки» for categories, choice stored 6 months, Consent Mode v2.
- **Links:** the logo goes to the homepage (on the homepage it scrolls to the top). Every card and button has a destination. In-page actions (filters, «Покажи още», «Копирай адреса», PDF download, wizard steps) are `<button>`s, not links.
- Contact wizard: 3 steps + done, topic preselected from the page the visitor came from.

## 8. Accessibility baseline

- Semantic landmarks (`header`, `nav`, `main`, `footer`), a skip link, exactly one H1 per page, no skipped heading levels.
- Every interactive element is reachable and operable by keyboard, with a visible `:focus-visible` state.
- Every link and button has an accessible name. Icon-only controls get an `aria-label` from `messages/*.json`.
- Every image has alt text (decorative art gets `alt=""`). Media uploads require alt text in Payload.
- `lang="bg"` on Bulgarian pages.
- Hover-only effects are under `@media (hover: hover)`; keyboard focus gets the same visual state.

## 9. Definition of done (per page)

A page PR is done when all of these hold:

1. **Matches Figma** at 1440 and 390 px: side-by-side with `get_screenshot` of the desktop and mobile nodes, saved in `docs/screenshots/<page>/`.
2. **Layout audit** at 1440, 1024, 768, 390 and 360 px: no horizontal overflow, no colliding neighbours, nothing off the page edge, and every card and button keeps its hover and its link. A Playwright test asserts `document.documentElement.scrollWidth <= innerWidth` at each width.
3. **Lighthouse** (mobile, lab, median of 3 runs), proposed targets: Performance ≥ 90 (desktop ≥ 95), Accessibility 100, Best Practices 100, SEO 100, LCP ≤ 2.5 s, CLS ≤ 0.05, TBT ≤ 200 ms. The user may change these; Lighthouse CI enforces whatever is in `lighthouserc`.
4. **axe clean:** zero violations from `@axe-core/playwright` on the page at both widths, including open states (menu, filters sheet, wizard steps, cookie settings).
5. **Reduced motion respected:** a Playwright test with `reducedMotion: 'reduce'` checks that no landing animation runs and strips and globe are still.
6. **Content rule respected:** no invented content; empty fields hide their element.
7. **Strings:** every fixed UI string comes from `messages/bg.json` with a key that is listed in `docs/i18n.md`.

## 10. Git (summary; the full rules are `docs/git-workflow.md`)

- **Planned steps go straight to `main`** (the user's decision, 31.10.2026). No branch or PR unless the user asks for one. Never force-push `main`.
- One step from `docs/pr-plan.md` at a time, as small Conventional Commits that each build.

- What a PR description would hold (summary, Figma links, deviations, open items) goes in the body of the step's last commit. Open items also go into § 12, and the Figma side-by-side screenshots into `docs/screenshots/`.

Decisions this package proposes (confirm before the PR that needs them):
- Halftone is applied only to art, never to photos (resolves a conflict in the brief; see `docs/cms-schema.md`).
- Amounts in лв: Bulgaria has used the euro since 01.01.2026. Ask whether funded-project amounts show the contracted лв amount, the euro amount, or both. Never convert silently.
- Translation page counter: characters counted with spaces, and how pages are rounded.
- Inquiry routing for non-language programmes (default: office@).
- Upload limits for translation documents.
- gtag.js or GTM; whether the Facebook Pixel stays; Consent Mode basic or advanced (`docs/measurement.md`).
- Map on the contact page: Google Maps embeds need consent; proposal is a static map image plus a link.
- Redirect targets for Language-Certificates, Entry-Level-Tests, Online-Education and Learning.
- Uploaded originals keep their EXIF (phone photos can carry GPS). Tints drop it, and `next/image` re-encodes everything it serves, but the original file stays reachable at `/api/media/file/…`. Proposal: strip EXIF from photo and scan originals on upload; logos stay byte-exact.

## 13. When in doubt

Ask the user rather than guess, in the PR description or in chat. Always ask about: infrastructure choices, any change to the agreed URL scheme, any content you can't source, and any deviation from the design.
